## Obligations fonctionnelles et typage

Le périmètre E01–E31 est validé. D = documenté dans le contrat, J = observé dans un JSON, V = testé sur les cas de campagne fournis, T = test/clarification à faire. Aucun nouveau test HTTP pendant L0. Le niveau de preuve ne retire aucune fonction.

Les drapeaux required d'OpenAPI ci-dessus ne suffisent pas : C exige fonctionnellement rome pour les statistiques métier et zonage + territoire (territoire omis seulement pour France) sur /indicateurs et /secteurs. Les requêtes doivent les fournir. Dix routes n'ont pas de schéma200 officiel ; les modèles enrichis restent non officiels. Les champs de match multicompétences et l'enveloppe comparaison de depuis ne sont pas complètement décrits par les schémas statiques, mais le contrat décrit ces variantes.

- Identifiants en chaînes, même numériques : ROME V3, OGR six chiffres avec zéros initiaux, Certif Info, RNCP, Formacode et territoires.
- Pagination documentée des listes : items, total, page_size, page, last_page ; page>=1. /domaines, statistiques et /mesures ne reçoivent pas de page. /domaines accepte seulement grand_domaine, sans q ni fields.
- Champs numériques : entier/nombre suivant définition, null admissible selon champ ; effectifs/taux soumis au secret peuvent valoir la chaîne secret_stat. Pas de coercition de chaîne arbitraire.
- Définitions/appellations/codes multiples : tableaux de chaînes ; blocs RNCP competences/modalites_evaluation : textes. Tags booléens nullables : null n'est pas false.
- Catalogue : items[].source ; résultats : source_libelle. Grain/période souvent en tête, sous items[] pour /indicateurs. L'unité vient de la définition du champ ; aucun champ unite uniforme n'est supposé.
- /recrutements : zonage region/departement/clpe, region seulement pour departement/clpe, departement seulement pour clpe ; pas de territoire. /salaires : region/departement et region seulement pour departement ; ni territoire ni tri. /sessions_* : region/departement/clpe et territoire requis ; France/commune non admis par enum malgré une description contradictoire.
- /metiers filtre domaine = Domaine professionnel ROME ; /competences filtre domaine = domaine de compétences1–6 ; /formacodes filtre domaine = domaine Formacode. Ne pas réutiliser un code entre ces paramètres homonymes.

## Correspondances des identifiants

- `/metiers` `items[].rome_code` → `/metiers/{rome}` et `/metiers/{rome}/competences` ; correspondance ROME V3.
- `/metiers/{rome}` `metiers_proches_codes[]` → `/metiers/{rome}` (un appel par cible sélectionnée).
- `/competences` `items[].competence_code` (OGR) → `/metiers?competence=...&mode_competence=toutes|au_moins_une`. Pour conditions, `/metiers?contexte=...` ou `sans_contexte=...`. R23/R24 contrôlés sur échantillons.
- `/certifications` `items[].certifinfo_code` → `/certifications/{certifinfo}` ; `fiche_code` ou `certifinfo_code` → `/certifications/blocs` ; `rome_codes[]` → fiches métier.
- `/territoires` `{zonage, territoire_code}` → `/indicateurs?zonage=...&territoire=...&rome=...` ; sur /indicateurs avec zonage=france, territoire est omis. Ne pas passer un code territoire à un endpoint dont la signature est différente.
- `/mesures` `items[].code` ↔ `/indicateurs` `items[].mesure` : jointure de résultats documentée, pas paramètre d’entrée.
